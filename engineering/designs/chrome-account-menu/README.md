# Chrome風のアカウントメニュー案

2026-11-06。ユーザーがこの案を採用した。下記の画像は画像生成ツールによるモックアップで、実画面や認証成功の証拠ではない。表示するユーザー名・メール・残高はサンプル。実装と確認の記録は[プロフィールメニュー実装](../../chrome-account-menu.md)を参照。

## 見た目

- 右上は高さ40〜44pxのプロフィールチップ。未ログインでは人物アイコンと「ログイン」、ログイン後は丸いアバターと名前を表示する。
- チップの直下に右揃えでメニューを開く。目安幅360px、角丸24px、薄い影、白〜淡いグレーの面。背景全体は暗くしない。
- メールと大きな丸いアバターを上部にまとめ、操作を下へ並べる。青はログイン操作やアカウントの識別に使い、現在の濃いオリーブ色のサイドバーと合わせる。
- 狭い画面は左右16pxを残してメニュー幅を縮め、ヘッダーの名前は省略できる。メニュー内ではメールを確認できるようにする。

## 状態ごとの案

1. [未ログイン](01-signed-out.png)：右上の「ログイン」からメニューを開き、標準の「Googleでログイン」ボタンを押す。中央のウェルカム画面には重複したログインボタンを置かない。
2. [認証中](02-auth-pending.png)：スピナーと「Googleの画面で操作を続けてください。」を表示する。予定の読み込みや成功と区別し、すべてのログイン入口で二重操作を防ぐ。残り秒数や進捗率は推測して出さない。
3. [ログイン済み](03-signed-in.png)：本人のメール・アバター・名前と、Googleカレンダーの実際の連携状態を表示する。「設定」「別のアカウントを使用」「ログアウト」を並べる。画像は連携済みの例で、未連携なら「Googleカレンダーを連携」と案内する。

## 操作

右上のプロフィール → メニュー → Googleでログイン → Google公式のアカウント選択 → 管理画面へ復帰 → 本人の予定を読み込む。初回の読み込みには既存のスケルトンを使う。正常に読み込めたらメニューを閉じ、右上を本人のプロフィールへ切り替える。ログイン済みの画像は、その後メニューを開き直した状態。

メニューは外側のクリックとEscで閉じ、フォーカスを元のチップへ戻す。「別のアカウントを使用」もGoogle公式のアカウント選択へ進める。ログイン処理がキャンセルされたら通常のボタンへ戻し、接続エラーの場合は再試行できる短い説明を示す。

実装ではAngular MaterialのMenu・Button・Progress SpinnerとMaterial Symbolsを使う。本人表示はFirebaseの認証ユーザーにあるdisplayName・photoURL・emailを使い、画像がなければイニシャルへ戻す。作業プロフィールの任意入力名と、Googleのログインアカウント名は区別する。

ログインだけでGoogleカレンダーを連携済みにしない。CalendarのOAuth同意は既存の連携処理として扱う。アカウントが変わった時点で前の課題や残高を消す既存処理も維持する。複数アカウントの一覧やChromeブラウザープロファイルの追加機能は、この提案では作らない。
