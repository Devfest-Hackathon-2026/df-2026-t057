# CIの3ジョブ分離と実行頻度の整理

## 構成と頻度

`changes` → `api` と `frontend` を並列 → `e2e` → 集約 `check` → 最新mainの配信対象だけ `cd.yml`。テストの3ジョブに加え、軽い変更判定と必須ステータスを残すための集約ジョブがある。

影響するアプリは `.github/ci-paths.yaml`、実行頻度は副作用のない `deploy/ci-policy.mjs` に置く。通常PRは主要操作のスモーク、認証・報酬・保存・API契約・CIの実行条件などはPRでも全件、mainのアプリ・配信対象変更は全件とする。テストやCI専用設定だけの変更では配信しない。単体テストだけの変更ではブラウザーを起動しない。生成物確認は生成に影響する変更に絞る。

コードフリーズまで2日のため、定期実行・依存更新の自動化は追加しない。`workflow_dispatch` は全件を手動確認するためだけに用意し、手動実行からCDは起動しない。

## 重複ビルドとキャッシュ

通常PRではAPI・Web・拡張を必要な分だけ一度ビルドする。Playwrightはビルド済みAPIを起動し、拡張のglobal setupでの再ビルドを省く。

mainの配信対象と、ビルド設定・受け渡しを変更したPRでは、Dockerイメージを一度作り、その同じイメージをデモモードで起動して全E2Eを実行する。mainだけ成功後にイメージを圧縮してartifactでCDへ渡す。CDはロードしたイメージIDを期待値と照合し、一致する場合だけpush・配信する。CDでは再ビルドしない。イメージの改変・破損時は配信へ進まない。

Go・pnpmの既存キーと復元先を維持する。Dockerは既存のproductionスコープを復元し、書き込みはmainに限定する。失敗時の証拠と必要な配信イメージの受け渡しartifactは3日保存する。PRでは本番の認証・push・配信を行わない。

## 取消と配信

api/frontend/e2eはジョブごとのconcurrencyグループで古い検証を取り消す。mainと手動検証はグループを分ける。親ワークフロー全体の取消をCDに伝播させない。

`check` とCD開始時に最新mainのSHAを確認する。古い合格コミットは配信対象から外す。CDは別のproductionグループで直列実行し、開始済みの配信は中断しない。配信前後のhealth・未認証拒否、失敗時の復旧は既存の `deploy/cloud-run.sh` を使う。GoogleのIAM・OIDC設定は変更しない。

## 確認

macOS arm64・Node 24.22.1・pnpm 12.15.0で、変更前の設定が新しい取消・イメージ受け渡しの回帰テストに失敗することを確認してから変更した。

- `pnpm --filter @dopagaki/deploy test`：判定・ジョブ依存・失敗/取消・最新main・同一イメージ・破損/不一致・起動時の接続リセット・コンテナーの待ち受け・配信復旧の58件が成功。
- `pnpm check`：フォーマット、Go/TS/CSS/API仕様/コントラストのLint、型確認が成功。
- `actionlint .github/workflows/check.yml .github/workflows/cd.yml`、`bash -n deploy/current-main.sh deploy/save-image.sh deploy/load-image.sh`、`git diff --check` が成功。
- `pnpm --filter @dopagaki/e2e exec playwright test --list --grep @smoke`：4ファイル・4件を選択。全件テストは残す。
- ビルド済みAPI・拡張を使うスモーク4件は11.9秒で成功。コンテナー内は既存の `DEMO_PUBLIC=true` で待ち受け、ホスト側のポートはlocalhostだけに公開する。起動直後の接続リセットでもhealthを再試行する。

Docker上の全件E2EとPRでCDが省略されることはActionsで確認し、結果をPR本文に記録する。本番のOIDC認証・配信はmainへマージするまでは未確認であり、ローカルのモック試験と区別する。
