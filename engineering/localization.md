# 日本語と英語への対応

2026-11-08。管理画面、Chrome拡張、サーバーが作る文（カレンダーの予定、AIの返答、通知）を、日本語と英語の2つの言語で表示できるようにした。

## 決めたこと

- **言語は本人のプロフィールに持つ。** `Profile.locale`（`ja | en`）を追加した。管理画面、拡張、APIの3つが同じ値に従う。そうしないと、画面は英語なのにカレンダーの予定や相棒の一言が日本語になる、といったずれが起きる。
- **最初の言語はブラウザーで決める。** サーバーはブラウザーの言語を知らないので、まだ保存していないプロフィールの既定値は日本語にした。管理画面は、版が0（一度も保存していない）のプロフィールを読み込んだときに、ブラウザーの言語（`navigator.languages` のうち、`ja` か `en` で最初に当たったもの。どちらも無ければ英語）で保存し直す。ログイン前の画面と、拡張がプロフィールを取得する前も、同じ方法で決めた言語を使う。
- **文言は `packages/messages` に、言語ごとのTSのオブジェクトとして置く。** `ja/` と `en/` に、`shared`（webと拡張で共有）、`extension`、`web` の3組がある。英語の側は日本語の側のオブジェクトの型に合わせているので、キーが抜けたり余ったりすると型エラーになる。空文字の訳し忘れは単体テストで見つける。
- **管理画面は、言語の signal から文言を引く。** `core/i18n/LocaleStore` が、言語・その言語の文言・`Intl` に渡す名前を signal で持つ。言語が変わると、`<html lang>`、Angular Materialの日付の部品、ページのタイトルも切り替わる。日時のパイプは言語を signal から読むため、`pure: false` にした。
- **サーバーが作る文は、本人の言語で作る。** `platform/locale` に `Locale` 型を置き、`profile`・`calendar`・`shortcut`・`companion`・`assistant`・`task` が使う。カレンダーの予定の説明、就寝の予定、デモ用の課題、ショートカットの通知の決まった文は、言語ごとの対応表から引く。Geminiへの指示文は日本語のままにして、返答の言語と長さだけを言語ごとに指定する。言語を変えたら、タイムゾーンを変えたときと同じジョブで、カレンダーの予定を書き直す。
- **相棒の一言の検証は言語ごとに分ける。** 英語は同じ内容でも文字数が多いので、表示できる長さの上限を60文字から140文字に広げた（AIへの指示は40文字と100文字）。使わない言葉には英語の語も足し、AIが指示と違う言語で返すこともあるため、言語によらずすべての語を確かめる。

## 見送った案

- **`@angular/localize`（Angular標準のi18n）**：言語ごとに別のビルドを作るので、画面を開いたまま言語を切り替えられない。また、Goが配信する `index.html` は1つで、CSPのnonceを埋め込んでいる（`apps/api/internal/adapter/http/web.go`）。言語ごとのビルドにすると、この配信の仕組みも変える必要がある。拡張と文言を共有することもできない。
- **ngx-translate や Transloco**：実行中に切り替えられるが、文言をJSONで持つのでキーの抜けが型で見つからない。依存も増える。
- **サーバーが `Accept-Language` で言語を決める**：拡張のservice workerやCloud Tasksのジョブなど、ブラウザーを通らない処理でも言語が要るので、保存した値を正にした。

## 拡張

- background がプロフィールの言語を取得して状態に持ち、content script とポップアップはその状態に合わせて文言を引く。プロフィールを取得する前と未接続の間は、ブラウザーの言語を使う。
- 拡張の名前と説明は、Chromeの仕組み（`public/_locales/{ja,en}/messages.json`）で切り替える。`default_locale` は英語にした。
- 状態に `profile` を足したので、前の版で保存した状態は読み込めず、未接続として扱われる。管理画面を開くと接続し直す。

## 確認したこと

2026-11-08、ローカル（`feat/localization`）で確認した。

- `pnpm run lint`、`pnpm run typecheck`、`pnpm run check`：すべて成功。golangci-lint は `mise exec --` 経由で実行した。
- `pnpm run test`：成功。管理画面 131件、拡張 137件、`packages/messages` 14件、Goは全パッケージ。
  - Go：`platform/locale`、カレンダーの説明と就寝の予定、ショートカットの決まった文、相棒の一言の検証、Geminiに送る指示文（日本語と英語）を確かめる。
  - TS：言語の選び方、英語の文言、空文字が無いこと、`LocaleStore` とページのタイトルの切り替え、設定画面で英語を選んだときの保存と表示の切り替え、拡張の言語の切り替えを確かめる。
  - 管理画面と拡張の既存のテストは日本語で動かす（`apps/web/src/testing/setup.ts`）。
- `pnpm test:e2e`：55件すべて成功。e2eは `locale: 'ja-JP'` なので、日本語の画面だけを確かめている。

## 確かめていないこと

- 英語の画面を、e2eやブラウザーで通しては確かめていない。英語の文の長さで表示が崩れないかも未確認。
- FullCalendar の言語の切り替えは、実装を読んで決めた。ブラウザーで、切り替えたあとに見出しが新しい言語になるかは確かめていない。
- 実際のGeminiが英語で返すか、英語の一言が140文字に収まるかは、実サービスで確かめていない。
