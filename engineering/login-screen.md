# 図で使い方を伝えるログイン前画面

2026-11-07。初めて訪れた人にも用途が伝わるよう、ユーザーが採用した「AIで課題を小分け → タイマーで取り組む → 作業でShortsの視聴時間が増える」の案を実装した。

## 表示と認証

- [LoginScreen](../web/src/app/login-screen.ts)を未ログイン時の入口にした。サイドバーと管理画面のヘッダーはログイン後に表示する。既存のURLとクエリは維持し、ローカルデモは従来どおり管理画面へ直接進む。
- 長い説明文を置かず、課題のメモ・タイマー・ブラウザー内のShortsを図でつないだ。狭い画面では図とラベルを縦に並べる。
- 図の「完了」はコンポーネント内のサンプル表示だけを切り替える。本人の課題登録・作業開始・報酬付与・状態取得のAPIは呼ばない。操作名と読み上げでもサンプルであることを示す。
- Googleログインは既存の`Api.login()`を使う。初期読み込み中と認証中はボタンを無効化し、待ち状態・キャンセル・失敗を表示する。ログイン後は既存の管理画面とアカウントメニューを使う。
- ButtonとProgress SpinnerはAngular Material、アイコンは既存のMaterial Symbolsを使用。ロゴとGoogleマークも既存素材を使い、図はHTML/CSSで構成した。外部画像や新しい依存関係は追加していない。

## 検証

- 環境：macOS、Node.js 25.7.0、Go 1.27.3、Playwright Chromium。アプリの前提環境は既存READMEのとおり。
- `npm run build`：Angular本番ビルドとChrome拡張のビルドが成功。
- `npm run typecheck`・`npm run test:unit`：成功。単体テスト17件には、認証中の二重送信防止・キャンセル後の復帰・アカウント分離が含まれる。
- `E2E_PORT=4217 npm run test:e2e -- --workers=2`：29件中27件が成功。拡張2件は接続先が4200のままでローカルAPIの4217と不一致だったため、`APP_URL=http://127.0.0.1:4217 npm run build:extension`で接続先を合わせ、失敗した2件だけ再実行して2件とも成功（38.2秒）。合計29件の確認が完了した。既存のカレンダー・課題・相談・設定・記録・拡張の回帰確認に加え、未ログイン時のサイドバー非表示、サンプル操作が個人データAPIを呼ばないこと、初期読み込み中のログイン無効化、認証設定エラーの表示と解除、デモでの既存画面復帰とクエリ維持を確認した。
- 新しいE2Eの未ログイン表示には、Firebase設定を含まないローカルの設定応答を使用。実際のGoogle認証成功を示す試験ではない。
- 1440px幅と320px幅の実装画面を確認。320pxでも横方向のはみ出しはなく、図とログインボタンが表示される。画像は`test-results/login-desktop.png`・`test-results/login-mobile.png`へ出力する。
- 整形チェックと`git diff --check`が成功。

実際のGoogleログインは行っていない。本番配信結果は配信後に追記する。

## 現行mainへの統合

本番反映では最新main `8150d60` を土台にし、設定・記録、視聴ルール、睡眠、セキュリティ修正を維持した。現行ルールは「5分の作業につき視聴1分」で、課題完了の定額20分は廃止されているため、図の例を「25分の作業で視聴5分」へ合わせた。課題完了・報酬付与のAPIは変更していない。

検証対象はこのmain統合版。ローカルの元作業ブランチ全体を本番へ上書きしていない。

## ログイン画面の簡素化（2026-11-08）

本人の選択に合わせ、ロゴ・キャッチコピー・短い一文・Googleログインだけを中央に置く構成へ変更した。説明図、サンプル操作、入口のフッターを取り除いた。プライバシーポリシーの公開ファイルと、ログイン後の設定・アカウントメニューからのリンクは維持している。

- `apps/web/public/logo.png`を幅26.25rem（標準の文字サイズで420px）で使用。今回添付された画像と460×120の全画素が一致しており、マーク・文字・縦横比は変更していない。
- 「やることを、次の楽しみに。」は従来の`headline-medium`の大きさを維持。補足は「課題を進めた分だけ、Shortsを楽しめる。」とし、英語も共通文言パッケージに定義した。
- 認証は現行の`AuthService`を使用。初期化中・ログイン中の無効化、エラー解除、設定取得の再試行を維持している。API、保存、報酬ルール、権限、実行環境の設定は変更していない。
- 旧作業ブランチ全体は配信せず、最新main `43205e0`の構成に画面の変更だけを移植した。新しい依存は追加していない。

### 全件E2Eで見つかった日付依存の検査

PRの全件E2Eでは、カレンダーのアクセシビリティ検査だけが失敗した（63件成功）。日曜の夜に「3時間後」の課題を作ると作業予定が翌週の月曜に入るが、検査は現在の週を開いて予定を探していた。失敗時の画面には11月8日の週と11月9日の次の課題が表示されており、ローカルでも同じ失敗を再現した。

`e2e/tests/accessibility.spec.ts`で、作成した課題の`plan.start`を利用者と同じAsia/Tokyoの日付へ変換し、その日付のカレンダーを開くよう修正した。アプリの予定計算やカレンダー表示は変更せず、検査を弱めたり省略したりしていない。修正後、同じ夜の条件でカレンダー検査とライト／ダークのaxe・リフローが成功した。
