# CIの実行量とキャッシュの改善

## 背景と観測

2026-11-08、main `269efda` のワークフローを確認した。単一の `code` 判定でコード生成、Go・管理画面・拡張の検証、全E2Eを選んでいた。

[拡張ID修正PRの実行](https://github.com/a-sumikawa/devfest-2026/actions/runs/42452001319)ではcheckジョブが11分32秒。コード生成45秒、Lint等1分56秒、単体2分32秒、ビルド1分29秒、ブラウザー導入25秒、E2E3分55秒だった。E2Eは55件・1 worker。これは単発の観測であり、平均値ではない。

miseのツール本体の復元は成功していたが、Goモジュール・コンパイル・Lintのキャッシュを保存しておらず、生成ステップで依存を再ダウンロードしていた。本番コンテナーのビルドにも、実行間で再利用するキャッシュがなかった。

## 変更

- PRの実行範囲は `.github/ci-paths.yaml` に置く。API、管理画面、拡張、共通パッケージを分け、共通部分の変更では両クライアントを検証する。契約の変更ではGoも検証する。
- mainへのコード変更は全体検証を継続する。資料だけの変更でもcheckの結果を残し、重い処理は実行しない。PR更新時の旧実行のキャンセルと、mainの配信を途中で取り消さない設定を維持する。
- 拡張だけのPRは、管理画面・APIを起動する拡張E2E（`extension*.spec.ts`）を実行する。現在は2ファイル・3件。API、管理画面、共通部分、E2Eそのもの、共通設定の変更では全E2Eを実行する。アクセシビリティ検査を外さない。
- フォーマットとTS/CSSのLintはコード変更全体で実行する。GoのLint・raceテスト、各アプリの型確認・単体テストは変更範囲で選ぶ。CIの判定・配信の回帰テストはすべてのコード変更で実行する。
- Goモジュール・ビルド・golangci-lintを保存する。ツールとGo依存のハッシュを復元条件にし、Goソースが変われば新しいコンパイル結果も保存する。拡張・管理画面だけの変更では同じGoキーを再利用する。
- pnpmストアをツールとロックファイルのハッシュで保存する。`node_modules` は保存せず、毎回 `--frozen-lockfile` でインストールする。
- DockerはBuildxと `type=gha,scope=production` を使用する。PRの検証とmainの配信で同じスコープを使うが、GitHubの参照範囲の制約により、PRのキャッシュをmainから読むことはできない。mainで作ったキャッシュは後続PRから利用できる。
- コンテナービルド記録のartifact自動アップロードを止め、E2E失敗時の証拠は3日間保存する。Goの鍵はソース単位、pnpmの鍵はロックファイル単位、Dockerのスコープは固定とし、不要なキーの増殖を抑える。

ジョブ分割だけでは総実行時間を減らしにくいため、checkは1ジョブを維持した。テストの削除、worker数変更、有料サービスの呼び出し、本番配信・IAM設定の変更はしていない。`packages/bridge` も管理画面の依存なので、他の共通パッケージと同じくコンテナー検証・配信対象に含めた。

開発依存のjs-yamlとpicomatchは、実際のワークフローとパス条件を読み、拡張・API・管理画面・共通部分・main・資料・設定変更の実行選択を試験するために追加した。判定ルールのコピーをテスト側に持たせない。

## 検証

修正前のワークフローで回帰テストを実行し、拡張変更でも全体検証が選ばれることと、コンテナーのキャッシュ未設定を検出した。修正後のパス判定テスト18件と、既存の配信テスト6件が成功した。

ローカル環境はmacOS arm64、Node 24.22.1、pnpm 12.15.0、Go 1.27.3。HTTPテストはループバックの待受が許可された環境で実行する。

| コマンド | 結果 |
|---|---|
| `pnpm check` | フォーマット・Go/TS/CSS/API仕様/コントラストのLint・型確認が成功 |
| `pnpm generate` と `git diff --exit-code -- apps packages` | 成功。生成物に差分なし |
| `pnpm --filter @dopagaki/deploy test` | CI判定18件・配信6件、計24件成功 |
| `pnpm build` | Go・Angular・WXTが成功 |
| `pnpm --filter @dopagaki/e2e exec playwright test --list 'extension.*\.spec\.ts'` | 拡張の2ファイル・3件が選択された |
| `actionlint .github/workflows/check.yml` / `git diff --check` | 成功 |

`pnpm test` も同じNode 24.22.1で成功した（bridge 2件、messages 11件、拡張128件、管理画面126件、CI・配信24件、およびGoのraceテスト）。

`CI=true pnpm --filter @dopagaki/e2e exec playwright test --workers=1 'extension.*\.spec\.ts'` は終了コード0、2.6分。3件中2件は初回成功、通知・作業タイマーの1件は既存の再試行設定で成功した。初回は `extension.spec.ts:178` の再開後の「一時停止」ボタンが5秒以内に現れなかった。今回そのアプリ実装・テスト・再試行設定は変更していないが、原因は確定しておらず、安定性の確認済みとはしない。

Actionsでの全体検証とDockerキャッシュの利用確認は、PR作成後に記録する。

キャッシュがない最初の実行は短縮を保証しない。導入後のActions実測と請求額の削減は、設定の追加やローカルテストだけで確認済みとしない。
