## 1. プロジェクト概要

### 1.1 背景

2016年4月、熊本県は最大震度7を観測する大地震に見舞われた。4月14日の地震に続き、4月16日にも最大震度7の地震が発生し、県内各地に甚大な被害をもたらした。

それから約10年が経過した2026年7月28日、熊本県は再び大規模な地震に見舞われた。宇城市・氷川町では最大震度7を観測し、改めて自然災害の脅威を突きつけられることとなった。

二度の大地震を経験した熊本において、防災は過去の教訓にとどまらず、今を生きる私たち自身が向き合うべき課題である。

災害時には、多くの住民が避難を余儀なくされる。しかし、すべての住民が同じように避難できるわけではない。自力で移動できる人もいれば、車椅子や介助を必要とする人、医療的な支援を必要とする人もいる。

さらに、地域全体に目を向けると、避難所の収容人数には限りがあり、避難者の集中や移動手段の不足、道路状況など、個人だけでは解決できない課題も存在する。

一人ひとりにとって適切な避難方法を考えることと、地域全体として円滑に避難できる計画を立てること。その両方が求められている。

私たちは、熊本で繰り返された災害の経験を未来の備えにつなげるため、個人と地域全体の双方の視点から避難計画の作成を支援するシステムを開発する。

### 1.2 目的

本システムは、避難者の特性、避難所の収容状況、移動手段、地理情報などを総合的に活用し、地域全体の避難計画の作成を支援することを目的とする。

特に、以下の3点を重視する。

1. **個人に適した避難支援**  
   住民一人ひとりの身体状況や移動能力、必要な支援に応じた避難方法を提案する。

2. **地域全体を考慮した避難計画**  
   各避難所の収容状況や住民の分布を考慮し、地域全体の避難先や移動方法を計画する。

3. **避難計画の可視化**  
   避難先、移動手段、経路、支援状況を地図上で直感的に把握できるようにする。

### 1.3 解決する課題

- 避難者が特定の避難所に集中することによる収容人数の超過
- 高齢者や障がいのある人など、要配慮者に適した避難方法の不足
- 避難に必要な車両や介助者などの支援資源の不足・偏在
- 避難者の集中や道路状況による移動の困難
- 地域全体の避難状況を把握することの難しさ
- 個人の避難計画と地域全体の避難計画を調整することの難しさ

### 1.4 提供する価値

本システムは、避難計画の作成に必要な情報を集約し、個人と地域全体の状況を踏まえた計画案を提供する。

利用者は、誰が、どこの避難所へ、どのような手段と経路で避難するのかを確認できる。

また、避難所の収容状況や支援を必要とする人の分布を可視化することで、事前の防災計画や避難訓練に活用できる。

## 2. 対象ユーザー

### 2.1 想定ユーザー

| ユーザー | 主な利用目的 |
|---|---|
| 自治体・防災担当者 | 地域全体の避難計画の作成・確認 |
| 福祉施設・支援団体 | 要配慮者の避難支援計画の確認 |
| 一般住民 | 自分の避難先・経路の確認 |
| 要配慮者 | 自身の状況に応じた避難方法の確認 |
| 家族・介助者 | 支援が必要な人の避難方法を把握 |

### 2.2 利用者区分

**管理者**

対象地域の避難者、避難所、移動手段などの情報を管理し、地域全体の避難計画を作成・確認する。

**一般利用者**

自分自身、または支援する人の避難先、移動手段、避難経路、注意事項などを確認する。

ハッカソンでは管理者による地域全体の避難計画作成を中心に実装する。

## 3. システム概要

### 3.1 システムの基本構成

本システムは、次の4つの機能群から構成される。

**① 避難情報の管理**

避難者、避難所、移動手段、支援に関する情報を管理する。

**② 地域全体の避難計画作成**

避難者を適切な避難所へ割り当て、移動手段や避難経路を含む計画案を生成する。

**③ 個別避難計画の確認**

避難者一人ひとりの避難先、移動方法、必要な支援を確認する。

**④ 避難計画の可視化**

地図上に避難者の分布、避難所の利用状況、移動経路などを表示する。

### 3.2 システムの利用タイミング

本システムは、主に災害発生前の避難計画作成や防災訓練での利用を想定する。

将来的には、災害発生後の状況変化に応じた避難計画の見直しにも対応することを目指す。

## 4. 利用シナリオ

### 4.1 UC-001 地域全体の避難計画作成

**利用者：管理者**

1. 管理者が対象地域を選択する。
2. 地域内の避難者情報を読み込む。
3. 避難所の位置や収容人数などを確認する。
4. 利用可能な移動手段や支援資源を設定する。
5. システムが地域全体の避難計画案を作成する。
6. 避難所ごとの割り当て人数を確認する。
7. 避難者の移動方法や経路を地図上で確認する。

### 4.2 UC-002 個人の避難計画確認

**利用者：一般住民・要配慮者・家族**

1. 利用者が対象となる避難者を選択する。
2. 割り当てられた避難所を確認する。
3. 移動手段と避難経路を確認する。
4. 必要な介助や物資、注意事項を確認する。

### 4.3 UC-003 避難所の受け入れ状況確認

**利用者：管理者**

1. 管理者が地域全体の避難計画を表示する。
2. 各避難所の収容可能人数と割り当て人数を確認する。
3. 特定の避難所を選択する。
4. 割り当てられた避難者の人数や属性を確認する。

### 4.4 UC-004 避難計画の変更

**利用者：管理者**

1. 管理者が避難所の利用可否や収容可能人数などを変更する。
2. システムが変更後の条件に基づいて計画を再作成する。
3. 新しい避難計画と変更内容を確認する。

## 6. 画面要件

### 6.1 画面一覧

| 画面ID | 画面名 | 主な内容 |
|---|---|---|
| SC-001 | トップ画面 | システム概要、利用開始 |
| SC-002 | 地域設定画面 | 対象地域の選択・設定 |
| SC-003 | 避難情報設定画面 | 避難者・避難所・移動手段の設定 |
| SC-004 | 地域避難計画画面 | 地域全体の避難先と移動計画を表示 |
| SC-005 | 避難所詳細画面 | 収容人数・割り当て人数・避難者情報 |
| SC-006 | 個別避難計画画面 | 個人の避難先・経路・必要な支援 |
| SC-007 | 計画結果画面 | 計画の概要と未割り当て者などを確認 |

### 6.2 主要画面の要件

**地域避難計画画面**

本システムの中心となる画面。

- 対象地域の地図
- 避難所の位置
- 避難者の分布
- 避難所ごとの割り当て人数
- 避難者の移動経路
- 避難計画の概要

これらを一つの画面から確認できることを目指す。

**避難所詳細画面**

選択した避難所について、以下の情報を表示する。

- 避難所名
- 所在地
- 収容可能人数
- 割り当て人数
- 収容状況
- 利用可能な設備
- 割り当てられた避難者の情報

**個別避難計画画面**

避難者ごとの情報として、以下を表示する。

- 出発地点
- 避難先
- 移動手段
- 移動経路
- 推定移動時間
- 必要な支援
- 注意事項

## 8. 外部データ要件

### 8.1 必要なデータ

| データ | 主な用途 |
|---|---|
| 地図情報 | 地域・道路・避難先の表示 |
| 避難所情報 | 避難先候補の取得 |
| 避難所収容人数 | 避難者の割り当て |
| 避難所設備情報 | 要配慮者の受け入れ条件の確認 |
| 人口・避難者データ | 地域全体の避難計画作成 |
| 道路・経路情報 | 避難経路の取得 |
| 移動手段情報 | 徒歩・車両等の移動方法の設定 |
| 災害・ハザード情報 | 避難時の注意事項の確認 |

### 8.2 データの取り扱い

- 公的機関のオープンデータを優先して活用する。
- データの取得元と更新状況を確認する。
- 実データが取得できない項目には、デモ用のサンプルデータを使用する。
- サンプルデータは実際の情報と明確に区別する。
- 避難所の受け入れ可否や道路の安全性が未確認の場合は、その旨を表示する。

## 11. システムの適用範囲と留意事項

本システムは、主に事前の避難計画作成、防災教育、避難訓練などにおける利用を想定する。

システムが生成する避難計画は、利用可能なデータに基づく計画案であり、実際の災害時の安全性を保証するものではない。

また、避難所の収容人数は、必ずしも災害発生時に受け入れ可能な人数を示すものではない。

実際の避難行動では、行政からの避難情報、避難施設の開設状況、道路の被害状況、現地の安全情報などを優先する。

個人情報や健康・支援情報については、必要最小限の収集とし、ハッカソンのデモでは原則として架空の人物データを利用する。

## 13. 今後の展望

本システムは、個人の避難支援と地域全体の避難計画を一体的に扱うことを目指す。

将来的には、災害情報、道路状況、避難施設の受け入れ状況、移送手段などを連携させ、状況の変化に応じて避難計画を見直せる仕組みへと発展させる。

熊本で経験した災害を、次の災害への備えにつなげる。

一人ひとりに目を向けながら、地域全体で命を守る避難のあり方を考えることが、本プロジェクトの目指す姿である。
